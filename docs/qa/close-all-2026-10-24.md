## 2. Review findings of this run and what was done

Reviewed against the versions actually in use, checked today against the registries: Angular 22.2.3 (latest), TypeScript 6.0.3 (Angular's peer range), web-vitals 6.2.3 (latest), Yarp.ReverseProxy 2.3.0 (latest), Duende.IdentityServer 8.0.9 (8.0.10 is out), ASP.NET Core packages 10.0.12 (10.0.13 is out), Microsoft.AspNetCore.Identity.EntityFrameworkCore **10.0.3** (lags the rest of the stack).

Fixed in this run:

- **Config contract would have stopped every page.** The BFF wrote `"minimumClientVersion": ""`; the app's reader (already committed) refuses an empty field and uses `"0"` for "no floor". Gate run 1 failed 19 of 36 checks on this alone. The BFF now serves `"0"` when no floor is set, in the page element and in `/bff/flags` (`ReleaseSettings.EffectiveMinimumClientVersion`).
- **Flags read while the door failed threw.** Angular's resource throws on `value()` in the error state; `FlagsStore` now reads only through `hasValue()`, so a failed door reads as "every flag off" (fail closed), as the spec demands.
- **Final Web Vitals were lost on page hide.** The telemetry flush listener was registered before web-vitals registered its own, so the last metrics were queued after the batch had gone. The listeners are now registered after `onLCP/onINP/onCLS`, on `visibilitychange` (hidden) and `pagehide`, with `keepalive`.
- **Browser `confirm()` in the shell** replaced by `ConfirmDialog` (native `<dialog>`: focus trap, Escape, focus return, safe button first, red button for the losing choice).
- **Check tooling gaps**: error codes are now verified against the framework catalogue (135 worded codes all declared); dependency policy, exact pins and the approved list are enforced; bundle budgets are measured per locale (initial 372–388 kB against 400 kB warning / 500 kB error; largest lazy chunk 65 kB against 250 kB).

Found and **left for the owner** (backend or policy; not changed):

- `Clear-Site-Data` on logout still includes `"cookies"`; the document (C-15) says never, because the console shares the registered domain.
- `secrets/` is tracked in git (private keys, a Gmail app password shape in dev settings, Duende licence key); the 22 October audit already lists this. Rotate and untrack; nothing was printed here.
- Lookups: a tenant administrator can create **global** lookup categories/values every tenant sees (`IsGlobal` bound from the body under a tenant-scope permission). A01, high confidence.
- Passkeys: the recursive CBOR walker in `PasskeyMakers.AaguidOf` can be driven to a stack overflow by a confirmed user (A10, medium confidence, not executed).
- Open redirects in the BFF (`//host` on `?lang`, `/\` in `LocalPathOnly`) stay parked by the owner's earlier decision; the app only passes its own router paths.
- `CookieOidcRefresher` releases the refresh lock after a wait timeout it never acquired (lead, low).
- Production settings: `TrustedProxyAddresses` absent (rate limiter sees the front door's IP), BFF Redis password empty, Identity SQL `TrustServerCertificate=True`.
- Issued access tokens outlive Suspend and Sign-out-device until `AccessTokenLifetime`; the server-side session ends at once.
- The console reaches the `administration` domain (checker wall widened); the document names `feature-platform-people`. Either rename or keep and amend the document.
- `angular.json` budgets (500 kB warning / 1 MB error) are looser than the skill's 400/500; `size-report` applies the skill's numbers.
- Package patch lag listed above (owner's upgrade call; nothing changed).
